--- layout: default --- {%- comment -%} A module page. The intro prose comes from the page body; the lesson list is generated from `page.category`, so adding a lesson to a module is a front-matter change in one file and nothing else. `sort: 'order'` rather than the date Jekyll would use on its own. The dates here are publication dates — six of the DSP lessons share one to the day — so sorting by them put the two-horn interferometer first in Horn Construction and "Steps for Installing Software on a Computer" last in Software Setup. `order:` is set in each lesson's front matter and is the curriculum sequence. Layout, on the WVU Design System: a blue page-head band with the module photograph beside the text, the intro prose (when there is any) in the 16-of-24 reading column, then the numbered lesson list. The list band is not-quite-white when prose precedes it, so the two sections read as two, and white when it follows the band directly. The list item carries the class lesson-card and nothing else, on purpose: the build workflow counts that exact attribute on /all/, which uses the same markup. The Design System classes go on the card inside it; the list itself is a Bootstrap row-cols grid, which sizes its children without a column class on each. The two-digit number is printed by Liquid from the lesson's own `order`, not by a CSS counter, so that on /all/ the filter cannot renumber the curriculum. {%- endcomment -%} {%- assign lessons = site.categories[page.category] | sort: 'order' -%} {%- assign slug = page.category | slugify -%} {%- assign module_info = site.data.modules | where: 'category', page.category | first -%}
