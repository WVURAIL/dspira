--- layout: default --- {%- comment -%} A lesson, on the WVU Design System: a blue page-head band (module eyebrow, title, summary), then the breadcrumb, the lesson body, the audience tags, the previous/next pager and the tail, all in the 16-of-24 reading column. Previous/next walk the lesson's own module, in curriculum order. A curriculum is read in module order, and the dates are publication dates — several lessons share one to the day — so a chronological pager was close to random: "Next" from the horn-construction overview used to be the two-horn interferometer. Every lesson now carries exactly one category and an `order`, so the chain through a module is unambiguous. Only core Liquid here — one sort and one pass over the sibling list — because GitHub Pages runs Jekyll 3.9 and anything newer fails the build silently, serving the last good copy of the site. The `no-print` class marks the navigation furniture (breadcrumb, tags, pager) that a printed or save-as-PDF copy of a lesson does not want; the layout's print rules hide it. The wrapper class "prose" stays: the residual stylesheet targets it for images, tables and figures in the markdown. {%- endcomment -%} {%- assign module = page.categories | first -%} {%- assign siblings = site.categories[module] | sort: 'order' -%} {%- assign found = false -%} {%- assign takenext = false -%} {%- for s in siblings -%} {%- if takenext %}{% assign nextpost = s %}{% assign takenext = false %}{% endif -%} {%- if s.url == page.url %}{% assign found = true %}{% assign takenext = true %}{% endif -%} {%- unless found %}{% assign prevpost = s %}{% endunless -%} {%- endfor -%} {%- assign module_url = module | slugify | prepend: '/categories/' | append: '/' | relative_url -%}
